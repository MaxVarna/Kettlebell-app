# Архитектура MVP: интервальные гиревые тренировки

> Этот документ переводит утверждённый продуктовый flow в техническую основу. При расхождении с ранними черновиками приоритет имеют [PRODUCT_DISCOVERY.md](PRODUCT_DISCOVERY.md), [UX_FLOW_AND_SCREEN_CONTRACTS.md](UX_FLOW_AND_SCREEN_CONTRACTS.md), [RUNNER_DESIGN_BRIEF.md](RUNNER_DESIGN_BRIEF.md) и [MOTION_LANGUAGE.md](MOTION_LANGUAGE.md).

## 1. Граница первого релиза

Это не силовой дневник и не программа с подходами, повторениями, тоннажом, выбранным весом или подсчётом калорий.

MVP позволяет:

- собрать и сохранить последовательность движений;
- один раз задать общий для всей схемы ритм: подготовка → работа → отдых;
- задать число повторений всей последовательности (циклов);
- запускать новую или сохранённую схему;
- получать во время работы крупный таймер, текущую анимацию движения и спокойное превью следующего состояния;
- поставить тренировку на паузу, безопасно завершить её и увидеть простой итог;
- восстановить незавершённую тренировку после сворачивания или перезапуска приложения.

Не входят в MVP: аккаунт, синхронизация, социальные функции, планы на недели, измерение техники, рекомендация веса, показатели силового прогресса, серверная аналитика и библиотека пользовательских видео.

## 2. Техническая ставка

**React Native + TypeScript + Expo development build** для iOS и Android. Одна кодовая база подходит для спокойного нативного интерфейса, локальной базы и анимационных ассетов; development build нужен, чтобы не связывать продукт ограничениями демонстрационной среды.

**Local-first.** Всё нужное для тренировки — схемы, встроенный каталог движений, анимации, активная сессия и результаты — доступно на устройстве без сети. SQLite сохраняет данные между перезапусками приложения; это соответствует назначению `expo-sqlite`. [Документация Expo SQLite](https://docs.expo.dev/versions/v56.0.0/sdk/sqlite/)

**Никакой фоновой «секундной службы».** Мобильная ОС сама выбирает момент выполнения фоновых задач и рассматривает заданный интервал лишь как минимальную задержку. Поэтому фоновая задача не может быть источником точного интервального таймера. [Ограничения Expo BackgroundTask](https://docs.expo.dev/versions/v56.0.0/sdk/background-task/)

В активном runner экран удерживается включённым, пока это не отменено пользователем или системой. [Expo KeepAwake](https://docs.expo.dev/versions/v52.0.0/sdk/keep-awake/)

## 3. Модель предметной области

### Схема тренировки

```ts
type IntervalRhythm = {
  preparationSec: number;
  workSec: number;
  restSec: number;
};

type WorkoutScheme = {
  id: string;
  title: string;
  movementIds: string[];       // порядок имеет значение
  rhythm: IntervalRhythm;      // один ритм на всю схему
  cycleCount: number;
  createdAt: string;
  updatedAt: string;
  lastStartedAt?: string;
};
```

`rhythm` принадлежит схеме, а не движению. У каждого движения есть только идентификатор, порядок и контентное описание — никаких локальных таймингов, веса, стороны, подходов или повторений.

### Встроенное движение

```ts
type Movement = {
  id: string;
  name: string;
  thumbnailAsset: string;
  runnerMotionAsset: string;
  reducedMotionAsset: string;
  muscleMapAsset?: string;
  techniqueNotes: string[];
};
```

Это контент приложения, поставляемый вместе со сборкой. Каждая motion-пара состоит из статичной миниатюры, лёгкой петли для фазы работы и статичной альтернативы для Reduce Motion. Правила движения описаны в [MOTION_LANGUAGE.md](MOTION_LANGUAGE.md); медицинских выводов и процентных «зон нагрузки» здесь нет.

### Активная сессия

```ts
type RunnerPhase = 'preparation' | 'work' | 'rest' | 'paused' | 'completed';

type ActiveSession = {
  id: string;
  schemeSnapshot: WorkoutScheme;
  status: RunnerPhase;
  cycleIndex: number;          // 0-based
  movementIndex: number;       // 0-based
  phase: Exclude<RunnerPhase, 'paused' | 'completed'>;
  phaseStartedAtMs: number;
  phaseEndsAtMs: number;
  pausedAtMs?: number;
  pauseRemainingMs?: number;
  createdAt: string;
  updatedAt: string;
};
```

Перед стартом схема копируется в `schemeSnapshot`. Поэтому последующее редактирование сохранённой схемы не меняет уже начатую или завершённую тренировку.

### Итог сессии

```ts
type CompletedSession = {
  id: string;
  schemeSnapshot: WorkoutScheme;
  startedAt: string;
  finishedAt: string;
  status: 'completed' | 'stopped';
  completedCycleCount: number;
};
```

Итог фиксирует факт и длительность тренировки, но не превращается в журнал силовых показателей.

## 4. Движок runner-а

Движок — независимый от экранов конечный автомат. UI лишь отображает его состояние и посылает явные команды.

```text
ready
  → preparation
  → work
  → rest
  → work следующего движения
  → …
  → completed

Любая активная фаза → paused → та же активная фаза
Любое состояние до completed → confirm stop → stopped
```

### Основные правила

1. Оставшееся время не накапливается таймерами JavaScript. Оно вычисляется как `phaseEndsAtMs - now`.
2. Интерфейс может обновляться часто, но тики интерфейса не являются данными тренировки.
3. После возвращения в приложение движок берёт текущее время, проходит все завершившиеся фазы и показывает актуальную фазу. Если время телефона выглядит некорректным, сессия не «угадывается»: предлагается возобновить или завершить её явно.
4. Пауза сохраняет оставшееся время и отменяет целевое время фазы; при продолжении создаётся новое `phaseEndsAtMs`.
5. При переходе фазы состояние синхронно сохраняется до запуска эффекта звука, haptic или анимации.
6. Звук, haptic и локальные уведомления — вспомогательные сигналы. Их отсутствие не меняет логику таймера и не считается ошибкой сессии.
7. При включённой анимации на фазе `work` видна только анимация текущего движения; `preparation` и `rest` используют свои нейтральные позы. При отключённой анимации или `Reduce Motion` изображения полностью скрыты: runner оставляет крупные название движения, фазу и таймер, а на подготовке и отдыхе — только фазу и таймер.

## 5. Слои приложения

```text
app/
  navigation/       маршруты и системные sheet
  screens/          Главная, Сохранённые, Конструктор, Runner, Итог
  features/
    schemes/        создание, редактирование, валидация, запуск
    movements/      выбор и карточка движения
    runner/         конечный автомат, восстановление, системные эффекты
    history/        список завершённых сессий и итог
  data/
    sqlite/         миграции, репозитории, транзакции
    content/        встроенные движения и ассеты
  design-system/    токены, типографика, компоненты, светлая/тёмная темы
  shared/           время, идентификаторы, доступность, типы
```

Зависимости направлены только внутрь: экран знает feature, feature знает интерфейс репозитория, репозиторий знает SQLite. `runner` не импортирует навигацию и не зависит от компонентов UI.

## 6. Экраны и их ответственность

| Экран | Получает | Делает | Не делает |
|---|---|---|---|
| Главная | последние сохранённые схемы | даёт равный вход «Новая» / «Сохранённые» | не показывает дашборд или прогресс |
| Сохранённые | `WorkoutScheme[]` | показывает одну миниатюру первого движения, резюме и «Старт» | не рендерит полосу всех движений |
| Конструктор | черновик `WorkoutScheme` | редактирует единый ритм, порядок, циклы и название | не разрешает индивидуальные интервалы упражнений |
| Выбор движения | встроенный каталог | добавляет движение в конец схемы | не создаёт отдельную тренировочную программу |
| Деталь движения | `Movement` | показывает крупную схему и вторичную карту зон | не обещает тренировочный эффект |
| Предстартовый просмотр | валидную схему | показывает порядок и общий ритм, запускает snapshot | не меняет данные во время старта |
| Runner | `ActiveSession` | отображает фазу, время, движение, паузу и безопасное завершение | не редактирует схему |
| Итог | `CompletedSession` | подтверждает окончание и возвращает к схемам | не собирает метрики силы |

## 7. Локальные данные

Минимальные таблицы SQLite:

```text
workout_schemes(id, title, rhythm_json, cycle_count, created_at, updated_at, last_started_at)
scheme_movements(id, scheme_id, movement_id, position)
active_sessions(id, snapshot_json, state_json, updated_at)
completed_sessions(id, snapshot_json, started_at, finished_at, status, completed_cycle_count)
app_preferences(key, value)
```

- `scheme_movements.position` уникальна в пределах схемы и задаёт порядок.
- При перестановке или удалении движения схема и её позиции изменяются одной транзакцией.
- В MVP допускается максимум одна незавершённая сессия. При новой тренировке пользователь сначала явно решает судьбу старой.
- Светлая/тёмная тема, Reduce Motion, звук и haptic хранятся в `app_preferences`.

## 8. Критические сценарии

### Сворачивание и возврат

При уходе приложения в фон сохраняется последнее состояние. При возвращении:

1. читается `ActiveSession`;
2. движок пересчитывает фазу от сохранённого `phaseEndsAtMs`;
3. UI появляется уже на правильном шаге;
4. motion запускается с чистого кадра текущей фазы, а не пытается «догнать» пропущенную петлю.

Длительные фоновые задачи не используются для покадрового ведения тренировки: платформа не гарантирует их точность. Уведомление может быть добавлено как удобный сигнал, но не как обещание точного перехода между интервалами.

### Пауза и завершение

- Одно касание — пауза/продолжение.
- Завершение всегда требует отдельного подтверждения.
- «Остановить» создаёт `CompletedSession` со статусом `stopped`, сохраняя факт частичного занятия без выдуманных расчётов.

### Доступность

- Крупный таймер остаётся главным элементом независимо от темы.
- У каждой фазы есть текстовое название; нельзя полагаться лишь на цвет или анимацию.
- `Reduce Motion` убирает motion-ассеты и включает минималистичный текстовый runner без изображения.
- Управление совместимо с VoiceOver/TalkBack, масштабом текста и повышенным контрастом.

## 9. Вертикальные срезы разработки

### Срез 1 — «тренировка без сохранения»

Фиксированная тестовая схема из двух движений → подготовка / работа / отдых → пауза → итог. Проверяем конечный автомат на устройстве, аудио/haptic, блокировку экрана и Reduce Motion.

### Срез 2 — «собрать и запустить»

Конструктор с общим ритмом, добавлением и перестановкой движений, валидацией пустой схемы и предстартовым просмотром.

### Срез 3 — «сохранить и вернуться»

SQLite, сохранённые схемы с одной миниатюрой первого движения, быстрый старт, снимок перед началом и восстановление после сворачивания.

### Срез 4 — «надежность»

Тесты переходов конечного автомата, перезапуск на каждой фазе, смена темы, Reduce Motion, отсутствие звука/уведомлений, реальный Android и реальный iPhone.

### Срез 5 — «контент и полировка»

Набор проверенных движений, согласованные motion-ассеты, карта зон как вторичный слой, микрокопирайт, финальные UI-состояния и проверка тренером контента движений.

## 10. Критерии готовности MVP

- Невозможно создать схему без движения, общего ритма или числа циклов.
- Изменение ритма в конструкторе меняет все фазы будущей тренировки одинаково.
- В активном runner-е нет полей веса, повторений, подходов или индивидуальных настроек движения.
- Сохранённая схема запускается за одно явное действие и не требует повторной настройки.
- После сворачивания или перезапуска время пересчитывается от контрольной точки, а не останавливается незаметно.
- Светлая и тёмная темы равноправны; главный таймер читаем при любом фоне.
- Эффект движения не мешает считывать фазу и время; при Reduce Motion доступен полноценный минималистичный режим без изображения.
- Результат тренировки и недавние сессии не заявляют силовой, медицинский или технический вывод.

## 11. Решения на будущее, но не сейчас

- Подсказка выбора веса возможна только после отдельной проверки формулировки тренером; она не должна сохраняться как параметр профиля или обязательное свойство упражнения.
- Сервер появляется лишь при очевидной потребности в резервной копии/синхронизации. Он не должен участвовать в запуске таймера.
- Если нативные возможности уведомлений или haptic потребуют специальной интеграции, они добавляются после проверки двух платформ, не меняя доменную модель.
- Визуальные ассеты до выпуска проходят отдельную проверку понятности и базовой техники движения.
