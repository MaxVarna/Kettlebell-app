# Audit Request adhoc-001 — UX/UI review of running build (off-cycle)

> Внеплановый UX/UI-аудит по прямому запросу владельца, вне стандартных gate 001–004.
> Метод выбран владельцем: живой обход веб-версии по ссылке + разбор в чате.

## Цель аудита

Независимо оценить usability и UI запущенной сборки приложения интервальных
тренировок с гирей: главный экран, конструктор тренировки, карточка движения,
активный runner (подготовка/работа/отдых), подтверждение завершения и пустое
состояние «Сохранённые». Найти проблемы, мешающие основному сценарию —
тренировке с телефоном на расстоянии вытянутой руки.

## Scope

### In scope

- Наблюдаемый UX/UI работающей веб-сборки (публичный туннель), снятой в браузере.
- 6 эвристических категорий: визуальный дизайн, юзабилити-эвристики Нильсена,
  UI-паттерны, human factors, UX-копирайт, информационная архитектура.
- Glanceability активного экрана, тап-зоны, состояния фаз, адаптивность вёрстки.

### Out of scope

- Исходный код, доменные инварианты, персистентность, тесты (этого auditor не читал).
- Реальные Android/iOS устройства и нативная сборка Expo.
- Сервер, аккаунты, sync, безопасность, публикация.
- Точные замеры контраста и наличие звука/вибро/Wake Lock — только визуальная оценка.

## Материалы для чтения

- Запущенная веб-сборка по ссылке вида `https://<...>.trycloudflare.com/` (эфемерная).
- `audit/AUDIT_POLICY.md`, `audit/reports/TEMPLATE.md` — формат заключения.

Auditor читал только работающую сборку и файл запроса; код проекта не открывался.

## Контекст

Основной продукт репозитория — Expo/React Native (`apps/mobile`). Проверялась
**веб-сборка**, открытая на широком десктопном вьюпорте, поэтому часть находок
по адаптивности специфична для web и может не относиться к нативному приложению.
Приложение mobile-first, домен — фитнес; ключевой сценарий — считывание фазы и
таймера во время упражнения.

## Что проверить в первую очередь

1. Читается ли фаза (подготовка/работа/отдых) с расстояния за доли секунды.
2. Достаточны ли тап-зоны для потных/движущихся рук (≥44px).
3. Есть ли обратная связь смены фазы, не завязанная на взгляд в экран (звук/вибро),
   и удерживается ли экран включённым.
4. Корректно ли ведёт себя таймер при подтверждении завершения.
5. Не ломается ли вёрстка веб-сборки на широком экране.

## Критерии оценки

- P0/P1 — существенные помехи основному сценарию тренировки.
- Отчёт явно отделяет наблюдаемое от непроверенного (код, звук, устройства, контраст).
- Находки конкретны: экран, элемент, последствие, рекомендация.
